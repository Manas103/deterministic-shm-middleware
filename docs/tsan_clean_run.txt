Note on check_snooper under ASan: one of its three checks deliberately
triggers a SIGSEGV (test_readonly_mapping_faults_on_write, proving a
PROT_READ mapping cannot be written to) and asserts on the signal via
waitpid/WIFSIGNALED/WTERMSIG. ASan's default signal handler intercepts that
SIGSEGV itself and reports it as an AddressSanitizer error before the parent
ever sees a normal signal exit, which fails the test for a reason that has
nothing to do with a real bug. Running with ASAN_OPTIONS=handle_segv=0 lets
the intentional SIGSEGV propagate normally; every other check in the suite
is unaffected by that option.
